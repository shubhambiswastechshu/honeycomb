{% load i18n %} {% comment %} Replaces the admin's 275px text sidebar with the app's icon rail, so crossing from /dashboard into /admin does not change what navigation looks like. Three things follow from that and are deliberate: * The id is `hc-rail`, not `nav-sidebar`. Django's nav_sidebar.js looks up `#nav-sidebar` and then `#nav-filter` unconditionally; renaming the element makes that script bail on its first lookup instead of throwing on a filter box this rail does not have. It also frees the rail from nav_sidebar.css, whose every rule is keyed on that id. * There is no toggle. The rail is 60px of icons -- there is nothing to reclaim by collapsing it, and a chrome element that can vanish is one the eye has to re-find on every page. * Labels live in tooltips, matching components/dashboard/IconRail.tsx. Each item still carries aria-label and title, so the name reaches assistive tech and the native tooltip even when the CSS one is not shown. `available_apps` comes from AdminSite.each_context, so this works on every admin page without a view change. {% endcomment %} {% url 'admin:index' as admin_index_url %}
